# Specification: GraphQL CodeGen Integration

**Track ID:** gql-codegen_20260505
**Type:** Chore
**Created:** 2026-05-05
**Status:** Draft

## Summary
Add `graphql-codegen` to the project to provide end-to-end type safety for the GraphQL layer. This includes typed resolvers for the backend and modern typed operations for the frontend.

## Context
The project currently uses raw string template literals for GraphQL queries in the frontend and manually typed (or untyped) resolvers in the backend. This leads to runtime errors and lack of autocomplete when changing the schema or queries.

## Acceptance Criteria
- [ ] `graphql-codegen` installed as a dev dependency.
- [ ] `codegen.ts` configured to handle both backend and frontend outputs.
- [ ] Backend resolvers in `src/Backend/graphql/resolvers.ts` are strongly typed using generated `Resolvers` type.
- [ ] Frontend operations in `src/features/jarvishAgent/constants.ts` use the `graphql()` tag from `client-preset`.
- [ ] All anonymous operations in the frontend are given descriptive names.
- [ ] `package.json` scripts updated with `codegen` and `codegen:watch`.
- [ ] The `start` script runs `codegen:watch` in parallel.

## Dependencies
- `@graphql-codegen/cli`
- `@graphql-codegen/client-preset`
- `@graphql-codegen/typescript`
- `@graphql-codegen/typescript-resolvers`

## Out of Scope
- Migrating the entire project to a GraphQL client library (like Apollo or urql). We will stick with `fetch()` but use the types generated by `client-preset`.
- Refactoring non-GraphQL code.

## Technical Notes
- We will use `graphql-tag-pluck` (included in codegen) to extract schema from `src/Backend/graphql/schema.ts` and operations from `src/features/jarvishAgent/constants.ts`.
- Frontend will use the `client-preset` to generate a `graphql` function that automatically attaches types to document nodes.
